# 内置 Word 模板与排版规范

本 skill 的两个模板位于 **skill 根目录下的 `assets/`**（本文件在 `references/` 下，不要按本文件的相对位置去找），不需要读取其他项目目录。模板是版式权威，排版规范只负责说明如何填充和检查，不重新设计模板。

运行本文件提到的脚本前，先用 `scripts/check_environment.py` 确认解释器状态；要用**装有 python-docx 的那个 Python** 运行，缺依赖时按 [setup-guide.md](setup-guide.md) 处理。

## 模板与页面

- `assets/活动案例模板.docx`：活动案例正文模板。
- `assets/团日活动总结表（团支部）.docx`：团支部总结表模板。
- 保留 A4 纵向页面、模板页边距、合并单元格、列宽、行高、附件编号、签章区域和原有层级。
- 生成时另存为副本，不覆盖原模板；总结表只填现有单元格，不重建表格。模板各行带整行禁拆属性，「活动过程及效果」填入长文本时由脚本恢复跨页断行，避免前一页留大片空白。
- 填充模板优先使用 `scripts/build_docs.py`（自动处理占位替换、注释行删除和固定版式）；手工填充时同样遵守本文件全部规则。
- 正式交付件删除模板中的排版说明注释行（如「（标题字体为宋体……）」「注：一级标题字体……」）和「（模板）」字样；「附件3：」「附件4：」编号行原样保留。
- 学院团委意见、盖章、签字和日期区域留空，不代填。

## 字体与段落

- 案例正文沿用模板的宋体、四号附近字号、固定 25 磅行距和首行约两字符缩进。
- 案例标题和二级标题沿用模板已有的粗体、字号和段前段后间距，不强行改成 Word 内置标题样式。
- 身份行写「学院全称 + 两个空格 + 团支部简称」两段，例如 `太原理工大学软件学院  软件2301团支部`。模板里的 `XX学院（全称）` 与 `XX团支部（简称）` 必须换成真实名称；把占位符原样留下，或直接把 `XX团支部` 当成支部名传进来，都会被审计脚本判为 ERROR。
- 心得体会/读后感没有内置模板，默认排版固定为：标题宋体三号加粗居中；身份行宋体四号居中；正文宋体四号、固定行距 25 磅、首行缩进两字符，与活动案例正文同族；正文保持自然分页。
- 总结表单元格文字继承模板字体、对齐和垂直对齐方式；长段落在“活动过程及效果”单元格内压缩。

### 要素级硬规则表（实测自内置模板，脚本与审计以此为准）

字号换算：小二=18pt，三号=16pt，小三=15pt，四号=14pt，小四=12pt。

| 要素 | 中文字体 | 字号 | 加粗 | 其他 |
|---|---|---|---|---|
| 附件编号行（附件3：/附件4：） | 宋体 | 四号 | 否 | 左对齐 |
| 文档大标题（材料提交案例） | 方正大标宋简体 | 小二 | 否 | 居中 |
| 案例主标题 | 宋体 | 三号 | 是 | 居中，段前段后各约1行 |
| 身份行 | 宋体 | 小四 | 否 | 居中，学院与支部间两个空格 |
| 一级标题（一、二、三） | 宋体 | 小三 | 是 | 段前段后间距沿用模板 |
| 二级标题（（一）（二）（三）） | 宋体 | 四号 | 是 | 固定25磅行距，首行缩进两字符 |
| 案例正文 | 宋体 | 四号 | 否 | 固定25磅行距，首行缩进两字符，两端对齐 |
| 总结表填写文字 | 宋体 | 小四 | 否 | 继承单元格水平/垂直对齐 |
| 心得标题 / 身份行 / 正文 | 宋体 | 三号 / 四号 / 四号 | 仅标题 | 居中；正文固定25磅、缩进两字符 |

注意：模板自带的排版“注”行与实际格式不完全一致（如一级标题标注四号、实际为小三 15pt）。以模板实际 run 格式为准，不要按“注”去“纠正”模板标题；生成副本时这些“注”行整体删除。

## 内容与版式边界

- 活动过程、互动环节、讨论内容、普通活动氛围和一般性活动成效可以根据通知合理生成，不要求逐项现场记录。
- 负责人、手机号、签名、公章、官方获奖、精确统计、人物原话等真实或证据性信息必须来自用户或通知。
- 活动日期可以是用户确认的单日，也可以是用户明确确认的跨天时间段；不要擅自改变用户的日期口径。
- 通知中的照片、邮箱、系统录入、截止时间和文件命名属于材料管理信息，不写入活动正文和 PPT 正文，除非用户明确要求。

## 渲染与审计检查

生成或修改 DOCX 后，按顺序执行两层检查：

1. **结构审计**：运行 `scripts/check_docx_format.py`，自动检查禁留占位（[待补]/XXXX/（模板）/注释行）、必含章节与顺序、字体字号行距缩进、总结表字段与学院团委意见空白、A4 页面；有 ERROR 必须修复后重跑。
2. **渲染检查**：运行 `scripts/render_preview.py` 导出逐页 PNG，逐页检查：

- 中文字体和字号是否正常；
- 标题、段落、表格是否溢出或贴边；
- 表格行高、分页、孤行和大面积空白是否合理；
- 身份行、日期、地点和总结表字段是否完整；
- 正式正文是否没有 `[待补]`。

如果当前环境没有渲染工具，至少进行 OOXML、段落和表格结构检查，并在交付说明中如实注明。

## 已知坑点与修法

实操验证过的高频问题，遇到对应症状时按下述根因处理，不要现场重新排查：

| 症状 | 根因 | 修法 |
|---|---|---|
| 总结表“活动过程及效果”整行跳到下页，前一页大片空白 | 模板全部表格行带 `w:cantSplit`（整行禁拆），长文本撑高行后无法跨页 | `build_docs.py` 已自动移除该属性；手工填充时同样移除后再交 |
| 保存 DOCX 报权限/占用错误 | 文件被后台 WINWORD 锁定 | 关闭后台 Word 进程或另存新文件，不在锁文件上硬写 |
| 渲染后标题字体变成了宋体/黑体 | 系统缺「方正大标宋简体」字体，渲染时被替换 | 交付前说明字体依赖；或征得用户同意改为系统已有字体 |
| 预览通过但用户打开后格式不同 | 渲染器与真实 Word 显示不一致 | 本 skill 一律用 Word COM 渲染（与用户 Word 显示同源）；换用其他转换器时必须注明并建议人工复核 |
| 模板“注”行残留或被当成正文保留 | 注释行与正式内容混排 | `build_docs.py` 按前缀自动删除；审计脚本会把残留标为 ERROR |
| 心得/案例正文被改用模板外的样式（如宋体五号、1.5倍行距） | 误把通用排版习惯带进来 | 全部交付物以本文件要素表为准；`check_docx_format.py` 会拦截 |
| 换了主题后案例主标题被报成三个版式 ERROR（行距、缩进、字号） | 曾按标题里的主题字面量判断主标题，主题一变就认不出来 | 已改为按结构识别：前言区＝首个章节标题之前的全部段落；若仍误报，说明模板结构被动过，按本文件要素表核对 |
| 身份行残留 `XX团支部` | 调用方把 `XX团支部` 当成支部名写进了 JSON | 传真实支部简称；`build_docs.py` 会打印警告，`check_docx_format.py` 会判 ERROR |
| 材料类型被认错（案例当成心得） | 曾按标题里是否出现固定词判断 | 已改为按结构特征判断：含「材料提交案例」抬头或两个以上章节标题→案例；首表含三个以上字段标签→总结表；其余→心得 |
